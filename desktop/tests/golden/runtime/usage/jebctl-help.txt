jebctl: install, supervise and update the desktop (phase 6). Exactly one JebDesktop at all times.

  status                  process, stamp, heartbeat age, last update result, versions
  migrate                 move the state folder from ~/.claude/jeb-desktop to ~/Library/Application Support/Jeb

  doctor                  read-only health check: one line per check (ok / FIX with the fix), exit 1 on a problem
                          (JEB_NO_LAUNCHCTL=1 skips the launchctl queries: `skipped (sandbox)`)

                          one short line per step (--verbose: every command and detail). First build through
                          the updater's compile, smoke and start gates (refuses if one fails; updates and
                          releases keep all gates), the
                          LaunchAgents, hand over from a run-live.sh instance, then bootstrap. Mode is
                          stored in JEB_HOME/install-mode (default: the stored one, else dev).
                          dev: the update agent ships local src edits through the gates.
                          release: no update agent; com.jeb.desktop.release runs `follow` every 6 h.
                          Release mode pins the signers: desktop/release-signers (ssh allowed_signers
                          format, in the repo) is copied to JEB_HOME/release-signers (0600) when that file
                          does not exist yet (trust on first install), from the cloned checkout before any
                          tag is looked at. Then tags are fetched and the clone moves to the newest verified
                          tag (signed by a pinned signer, commit on origin's default branch); with no signer or
                          no verified tag it stays on the cloned commit. --repin replaces the pin by hand. A bundle install
                          follows later releases' files instead: once a release is verified against the pin (and at the
                          start of each follow, from the installed release) its desktop/release-signers replaces the pin
                          when that release is newer than the one the pin came from (release-state signers_from).
                          Release mode never compiles: the release's prebuilt app (and its detect and png2raw helpers)
                          is used when it checks out (see follow); every gate still runs. With no verified prebuilt (no
                          network, no asset, a hash mismatch) the install stops
                          with a plain reason. --build-from-source (or JEB_ALLOW_BUILD=1) is the escape hatch: it
                          compiles as dev mode does (needs the Command Line Tools).
                          Last, `jebctl` is linked into ~/.local/bin (JEB_BIN_DIR); a different file already at that
                          path is left alone. The PATH is optional: one line says to run ~/.local/bin/jebctl, and
                          --add-path adds that folder to the shell profile (zsh ~/.zprofile, bash ~/.bash_profile,
                          else ~/.profile; JEB_PROFILE; backup first).
                          --no-agents (sandbox only, used by ./release smoke): everything above up to the install-mode file and
                          the plists in JEB_HOME/launchd, but no hand-over, no copy into LaunchAgents, no launchctl,
                          no wait for the desktop, no jebctl link (each prints `skipped (--no-agents)`). Refused
                          unless HOME differs from the account's real home and the app, LaunchAgents and state
                          folders are under HOME. `follow`, `reload-agents` and `rollback` take it too (sandbox tests).
                          Release bundle (<root>/bundle.json exists: ~/.jeb/versions/<tag>/ unpacked from a release zip): no git and no
                          compile. The bundle's app is gated (smoke, headless start) and swapped in, ~/.jeb/current is pointed at the
                          bundle, and the plists, the plugin entry and the ~/.local/bin link name only ~/.jeb/current paths. It runs with
                          the bundle's own Python (python/bin/python3 -I). --build-from-source and --mode dev are refused.
  uninstall [--purge] [--remove-files] [--purge-farm] [--dry-run] [--verbose]
                          one short line per step (--verbose: every command and detail). Bootout, remove the
                          plists and the app; versions and logs stay unless --purge (removes everything in JEB_HOME);
                          also the ~/.local/bin/jebctl link (only if it points here) and the PATH lines install added.
                          --remove-files and --purge-farm run the bundle's `uninstall` script with all the flags (it also takes
                          the plugin out of Claude Code (jeb@jeb and the "jeb" marketplace) and deletes ~/.jeb); see ./uninstall
  follow [--gates-only] [--quick] [--build-from-source] [--dry-run]
                          (bundle layout, see below; this describes the git-clone layout.)
                          release mode: fetch tags, then take the newest unseen v* tag that is signed by a
                          pinned signer (JEB_HOME/release-signers; none pinned: nothing happens) and whose
                          commit is on origin's default branch; any other candidate is recorded as failed
                          and the next older one is tried. The commit is pinned by SHA: git archive into
                          JEB_HOME/staging/<tag>/, the updater's gates against the staged src and mod,
                          only on a pass check the SHA out here and install the build, watch it, roll back
                          (checkout of the previous SHA and bundle) on failure. Skips if the clone is dirty
                          or not on a v* tag. --gates-only stops after the gates. Log: JEB_HOME/release.log
                          Progress and the final result (and why a check did nothing) go to JEB_HOME/update-status.json,
                          which the menu bar shows; the menu's click file JEB_HOME/check-now is cleared at the start.
                          The release's app (JebDesktop-<tag>-macos.zip: JebDesktop, detect and png2raw, universal) is
                          downloaded over HTTPS from github.com/<repo>/releases/download/<tag>/ (no sign-in) and used only when
                          its SHA-256 equals the app-sha256 line in the signed tag message and it holds this Mac's
                          architecture. Release mode never compiles: with no usable app the run stops with "app
                          download failed; will retry" and the tag is NOT marked failed (the 6-hourly agent retries).
                          --build-from-source (or JEB_ALLOW_BUILD=1) compiles instead. The gates run on the app.
  release [--bump auto|patch|minor|major] [--parity] [--dry-run]
                          (owner only, from a development clone, and refused in a release bundle: use ./release)
                          owner side: the clone is clean and on the default branch, a signing key is
                          configured (user.signingkey), then `claude plugin validate mod` and `validate .` (the marketplace), `claude plugin
                          test mod`, a universal release build (and the parity gate with --parity on that
                          same binary), then a local signed tag v<version> whose message carries the SHA-256
                          of the app zip (JebDesktop-<tag>-macos.zip, written to .git/jeb-release-<tag>/ for
                          ./release to attach; it holds JebDesktop plus the universal detect and png2raw helpers). The universal
                          native jebctl (desktop/cli, version baked in) is built into the same stage folder, beside that zip, and
                          ./release puts it in every bundle as desktop/bin/jebctl and attaches it as jebctl-macos; the signer
                          pinned in its source (signerLines) must equal the jeb-release lines of desktop/release-signers or the release stops.
                          The version comes from the tags, as release-please does: no tag yet is
                          1.0.0; else the last tag raised by --bump (default auto: the level from the
                          Conventional Commits since it; refuses when none is releasable). Only once every
                          check has passed is it written to mod/.claude-plugin/plugin.json and committed
                          ("chore(release): v<version>") before tagging. Release notes from the same commits go
                          to .git/jeb-release-notes-<tag>.md. Prints the push command; never pushes

JEB_HOME (state root), JEB_SRC (the app source, default src/ beside this script), JEB_APP_DIR (default
~/Applications), JEB_LAUNCHAGENTS (default ~/Library/LaunchAgents), JEB_BIN_DIR (default ~/.local/bin), JEB_PROFILE and
JEB_BACKUPS and JEB_TOOLS_DIR (the standalone jebctl, default ~/.jeb/bin) override the defaults, and JEB_RELEASE_BASE (where releases are read; a test server), mostly for tests. JEB_NO_LAUNCHCTL=1 (sandbox)
skips the launchctl calls.
Bundle layout, follow: the newest published release (github.com/<repo>/releases/latest, a web redirect, not the API) newer than the installed one (when that one was rejected, the older ones from releases.atom) is downloaded (manifest,
signature, this Mac's zip), verified against the pinned signers for the `jeb-release` namespace, unpacked beside the live version, gated,
then ~/.jeb/current is switched and the older folder removed (one version on disk). A git clone converts to this layout on its first
release-mode follow when a bundle release exists; the clone is left on disk (release-state legacy_clone).
In the git-clone layout DEVELOPER_DIR is set to the Command Line Tools only when the selected Xcode fails (its license never
accepted), so that license never blocks git or xcrun; a working Xcode is left alone.
The mod path rendered into the plists (JEB_MOD) is mod/ beside desktop/, from this script's own location.
